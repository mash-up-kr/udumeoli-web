# 기획 참조와 변경 관리

서비스 동작·화면·검증·권한·데이터 정책을 계획, 구현, 리뷰하거나 기획을 논의할 때 적용한다. 단순 포맷·도구 설정 등 제품 동작과 관계없는 변경에는 적용하지 않는다.

- 먼저 `docs/product/README.md`에서 관련 화면을 찾고 해당 문서·연계 플로우·관련 `OPEN_QUESTIONS.md` 항목을 읽는다. 결과나 계획에 적용 SPEC ID·항목과 필요한 Q ID를 남긴다.
- 코드의 현재 동작을 기획 승인 근거로 삼지 않는다. 기획 미기재·상충은 드러내고 필요한 결정만 질문한다. 영향을 받지 않는 작업은 계속한다.
- 명시적 정책 변경 요청은 승인 범위에서 문서에 즉시 반영한다. 아이디어·질문·가정은 확정하지 말고 구체적 변경 전후와 대상 문서를 제시해 반영 여부를 묻는다. 승인 없이 현행 기획을 바꾸지 않는다.
- 추출·정책 변경·미확정 등록·Figma 재동기화에는 `.claude/skills/product-spec/SKILL.md`를 직접 읽고 따른다. 자동 스킬 선택이나 심볼릭 링크 가용성에 의존하지 않는다.
- 리뷰에서는 적용 기획의 조건·예외·권한과 구현을 대조한다. 미확정에 기대는 구현을 확정 완료라고 보고하지 않는다.
- `MAP_SPEC.md`·`GOOGLE_MAPS_SPEC.md`와 충돌하면 이력과 사용자 결정을 확인한다. 날짜만으로 덮어쓰지 않는다.

# 과설계 방지 (Lazy Senior Dev)

**게으름 = 효율, 안일함 아니다.** 최고의 코드는 안 쓴 코드다. [behavior.md](behavior.md)의 "Simplicity First"를 구체적인 순서와 판단 기준으로 보강한다.

**Tradeoff:** 이 규칙도 정확성·보안·접근성보다 우선하지 않는다. 아래 "게으르면 안 되는 것" 참고.

---

## 코드 작성 전 사다리

코드를 짜기 전에 아래 순서대로 멈출 수 있는 첫 단계에서 멈춘다:

1. **이거 진짜 필요한가?** (YAGNI) — 아직 안 생긴 요구사항이면 스킵하고 한 줄로 이유를 남긴다.
2. **이미 이 코드베이스에 있나?** `src/shared` 유틸·훅, shadcn/ui 컴포넌트, 기존 패턴부터 찾는다. 몇 파일 건너에 있는 걸 다시 만드는 게 가장 흔한 slop이다.
3. **표준 라이브러리/런타임이 이미 하나?** (TS/Web API) 그거 쓴다.
4. **네이티브 플랫폼 기능이 커버하나?** `<input type="date">` > 커스텀 피커, CSS > JS, HTML 시맨틱 > `role` 땜빵.
5. **이미 설치된 의존성이 푸나?** 그거 쓴다 — 몇 줄이면 되는 걸로 새 패키지 추가 금지.
6. **한 줄로 되나?** 한 줄로 한다.
7. **그래도 안 되면:** 그때 최소한의 코드를 짠다.

사다리는 문제를 이해한 다음에 타는 반사동작이지, 이해를 건너뛰는 지름길이 아니다. 먼저 작업이 건드리는 코드를 읽고 실제 흐름을 끝까지 추적한 뒤 사다리를 오른다. 두 단계가 다 되면 더 높은 단계를 택하고 넘어간다.

## 버그 수정 = 증상이 아니라 원인

리포트는 증상 하나만 말한다. 고치기 전에 건드릴 함수의 **호출자를 전부 grep**한다.

- 게으른 수정이 곧 근본 원인 수정이다 — 공유 함수에 가드 하나 넣는 게, 호출자마다 가드 넣는 것보다 diff가 작다.
- 티켓이 지목한 경로만 패치하면 형제 호출자는 여전히 깨진 채로 남는다.
- 실제 사례: `Calendar` 컴포넌트가 `classNames`를 슬롯별로 통째로 덮어써서 호출부마다 매번 우회 클래스를 따로 붙였던 문제 — 컴포넌트 내부에서 `cn()`으로 병합하도록 한 번만 고쳐서 모든 호출부가 해결됨 (PR #75).
- [good-debug](../skills/good-debug/SKILL.md)가 개별 버그의 "원인 vs 증상" 판단을 다룬다면, 여기는 그 원인 수정을 "어디서" 할지(호출자 전부 vs 공유 지점 한 곳)를 다룬다.

## 규칙

- 요청받지 않은 추상화 금지 — 구현체 하나뿐인 인터페이스, 상품 하나뿐인 팩토리, 안 바뀌는 값의 config 금지.
- 요청받지 않은 새 의존성 금지.
- "나중을 위한" 보일러플레이트 금지 — 나중은 나중에 알아서 스캐폴딩한다.
- 추가보다 삭제. 클래버보다 뻔함. 파일 수는 최소로.
- 가장 짧은 동작하는 diff가 이긴다 — 단, 문제를 이해한 다음에만. 엉뚱한 자리의 최소 변경은 게으른 게 아니라 버그를 하나 더 만드는 것.
- 복잡한 요청 받으면 되물어라: "진짜 X 필요한가, Y로 되지 않나?"
- 크기 같은 stdlib 방식 두 개 중에선 edge case 정확한 쪽을 고른다 — 게으름은 코드를 적게 쓰는 것이지 부실한 알고리즘을 고르는 게 아니다.
- 명확한 한계를 가진 의도적 단순화(글로벌 락, O(n²) 스캔, 나이브 휴리스틱)는 `ponytail:` 주석으로 한계와 업그레이드 시점을 남긴다. 예: `// ponytail: 글로벌 락, 처리량 문제되면 계정별 락으로`

## 게으르면 안 되는 것

- 문제 이해 자체 — 사다리는 해법을 줄이지 이해를 줄이지 않는다. 실제 흐름을 끝까지 안 읽고 작은 diff부터 내미는 건 게으름이 아니라 위험한 확신범.
- 신뢰 경계(사용자 입력, 외부 API)에서의 검증
- 데이터 손실을 막는 에러 핸들링
- 보안, 접근성 ([good-a11y](../skills/good-a11y/SKILL.md) 참고)
- 명시적으로 요청받은 것
- 분기·반복·파서·금액/보안 로직처럼 사소하지 않은 로직은 실행 가능한 확인 하나(assert 기반 self-check 또는 작은 테스트 하나)를 남긴다. 프레임워크·픽스처 불필요. 한 줄짜리는 테스트도 불필요.
